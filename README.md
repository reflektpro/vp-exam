# ГУ ВП — Учебный центр (лекции и экзамены)

Отдельный сайт для кандидатов в ГУ ВП (RMRP, «Патрики»): вход через Discord → просмотр лекций без перемотки → экзамен → проверка экзаменатором.
Не связан с сайтом рапортов (vp-raport / curly-disk-ebd7) — свой Worker, своя база, своё Discord-приложение (или общее, см. ниже).

| Что | Где |
|---|---|
| Сайт (GitHub Pages) | https://reflektpro.github.io/vp-exam/ |
| API (Cloudflare Worker) | https://vp-exam-api.reflektpro8.workers.dev |
| База (Cloudflare D1) | `vp-exam-db`, id `ce68b5b2-5aa7-4b69-9f7a-edb1b1744cb9` |
| Discord Redirect URI | `https://vp-exam-api.reflektpro8.workers.dev/auth/callback` |
| Главные администраторы | Discord ID `417660389723996170`, `711459160268734505` (переменная `ADMIN_IDS`) |

## Как включить вход через Discord (обязательно, сейчас вход выключен)

Пока не заданы ключи, API отвечает «OAuth не настроен», а кнопка входа на сайте неактивна.

1. Откройте https://discord.com/developers/applications.
   - **Вариант А (рекомендуется):** «New Application» → назовите, например, «ГУ ВП Учебный центр».
   - **Вариант Б:** взять существующее приложение сайта рапортов. Тогда нужен его *текущий* Client Secret.
     ⚠️ Не нажимайте «Reset Secret» в существующем приложении — иначе сломается вход на сайте рапортов.
2. В приложении: **OAuth2 → Redirects → Add Redirect** и вставьте ровно:
   `https://vp-exam-api.reflektpro8.workers.dev/auth/callback` → **Save Changes**.
3. Там же скопируйте **Client ID** и **Client Secret** (для нового приложения — «Reset Secret», чтобы показать его).
4. Cloudflare Dashboard → **Workers & Pages → vp-exam-api → Settings → Variables and Secrets → Add**:
   - `DISCORD_CLIENT_ID` — тип **Secret** (можно Text, но Secret сохраняется при повторных деплоях через API);
   - `DISCORD_CLIENT_SECRET` — тип **Secret**.
   → **Deploy**. Или из консоли: `npx wrangler secret put DISCORD_CLIENT_ID` и `npx wrangler secret put DISCORD_CLIENT_SECRET` в папке `worker/`.
5. Проверка: https://vp-exam-api.reflektpro8.workers.dev/health должно показать `"oauth_configured":true`, а на сайте кнопка «Войти через Discord» станет активной.

Запрашиваемый scope — только `identify` (ID, ник, аватар).

## Архитектура

```
GitHub Pages (статический HTML/JS/CSS, без сборки)        Cloudflare Worker vp-exam-api            D1 vp-exam-db
index.html, app.js, player.js, admin.js, style.css  ──►  worker/worker.js (один ES-модуль)  ──►  users, sessions, lectures,
config.js (адрес API)        Authorization: Bearer        CORS только https://reflektpro.github.io     lecture_progress, exams, questions,
                                                                                                    attempts, answers, settings, audit_log
```

**Вход:** сайт → `GET /auth/login?return=<url сайта>` → Discord → `GET /auth/callback` (worker меняет code на токен Discord, читает `/users/@me`,
создаёт/обновляет пользователя, выдаёт одноразовый `login_code` на 2 минуты) → редирект на сайт `?login_code=…` → сайт делает
`POST /auth/exchange` и получает сессионный токен (хранится в `localStorage`, в базе — только SHA-256 хеш; срок 7 дней).
Cookie не используются (разные домены github.io / workers.dev), поэтому CSRF неактуален. `state` OAuth хранится в D1 (10 минут).

**Роли:** `candidate` (по умолчанию), `examiner` (проверка попыток, просмотр кандидатов), `admin` (всё).
ID из `ADMIN_IDS` всегда `admin` и не могут быть понижены/заблокированы через сайт. Назначать/снимать админов может только главный админ;
обычный админ может назначать проверяющих. Права проверяются на сервере в каждом запросе `/api/admin/*`.

**Защита от перемотки лекций:**
- Клиент: свой плеер без полосы перемотки (пуск/пауза, «назад 10 с», громкость, полный экран; скорость зафиксирована 1×),
  попытка перемотать вперёд дальше уже просмотренного откатывается, назад — можно. Продолжение с последней позиции.
  Видео ставится на паузу при скрытии вкладки (`PAUSE_ON_HIDDEN` в `config.js`).
- Сервер: плеер шлёт heartbeat каждые 10 с и при play/pause/ended. Прирост позиции принимается, только если он
  ≤ `реальное время с прошлого heartbeat × 1.1 + 2 с` и ≤ 40 с за раз. Иначе — отказ и откат (счётчик отказов виден админу).
  Лекция засчитана, когда `max_pos ≥ длительность − 3 с` **и** засчитанное время просмотра ≥ 95 % длительности.
- Длительность задаёт админ (кнопка «Определить по видео» читает её из файла). Если длительность указана больше реальной, лекцию нельзя будет досмотреть — проверяйте.

**Экзамен:** 20 типов вопросов (см. «Типы вопросов» ниже). Параметры: лимит времени, лимит попыток,
пауза между попытками, проходной %, перемешивание вопросов/вариантов, **«Обязательные лекции»**, публикация.

**Обязательные лекции экзамена** (блок в форме экзамена):
- «Все опубликованные лекции» — по умолчанию и для всех старых экзаменов: нужны все опубликованные лекции с отметкой «Обязательная» (как раньше, включая будущие).
- Галочки у отдельных лекций — экзамен откроется после просмотра только выбранных. Черновики и удалённые лекции не учитываются; в списке экзаменов про них показывается предупреждение.
- Ничего не отмечено и «все» выключено — экзамен открыт сразу, без лекций.
- Проверка выполняется на сервере при открытии карточки, старте и отправке попытки. Кандидат видит на карточке экзамена, какие лекции просмотрены и что «Осталось посмотреть» (со ссылками).
- Настройка «Открывать лекции строго по порядку» влияет только на очерёдность просмотра лекций, а не на допуск к экзаменам. Если нужная экзамену лекция стоит третьей, кандидату всё равно придётся посмотреть первые две, чтобы её открыть (на карточке такие лекции отмечены 🔒).
Правильные ответы и эталоны никогда не отправляются кандидату. Варианты проверяются автоматически (multi — только точное совпадение),
текстовые идут на ручную проверку. Таймер проверяется на сервере: после дедлайна (+30 с запаса) попытка завершается автоматически
с сохранёнными ответами (ответы автосохраняются каждые 15 с). Пока попытка на проверке или экзамен сдан — новая попытка не начинается.
Кандидат видит итог (СДАН / НЕ СДАН / НА ПРОВЕРКЕ), процент и комментарий проверяющего, но не разбор по вопросам.

## Типы вопросов

Все типы работают и в экзаменах, и в переаттестации. Проверка выполняется на сервере, правильные ответы клиенту не отправляются. Для каждой попытки сохраняется своё перемешивание и свои параметры.

| Тип | Проверка |
|---|---|
| Одиночный / множественный выбор (`single`/`multi`) | авто (multi — точное совпадение или частичный балл, если включён `partial`) |
| Ввод числа (`number`) | авто, допуск ±tolerance, единица, принимается десятичная запятая |
| Ввод текста (`text`) | авто, список допустимых ответов; регистр, ё/е и крайняя пунктуация не важны |
| Параметризованная задача (`param`) | авто: переменные `{A}` берутся случайно из диапазонов, ответ считается по формуле |
| Свободная форма (`long`) | вручную, проверяющий видит эталон |
| Последовательность (`order`) | авто; перетаскивание или стрелки ↑↓ (удобно на телефоне) |
| Соответствия (`match`) | авто, можно добавить лишние варианты |
| Пропуски — ввод / из списка (`blanks_input`/`blanks_select`) | авто, разметка `[[ответ|синоним]]` / `[[неверно|*верно]]` |
| Интерактивный диктант (`dictation`) | авто, выбор буквы или слова прямо в тексте |
| Последовательное исключение (`eliminate`) | авто: кандидат вычёркивает варианты, пока не останется один |
| Слайдер (`slider`) | авто, допуск ±tolerance |
| Загрузка файла (`file`) | вручную. Файл хранится в D1 (base64, ≤ 1 МБ), можно дать ссылку |
| Голосовой ответ (`voice`) | вручную. Запись в браузере (MediaRecorder) или загрузка аудиофайла, ≤ 1 МБ |
| Информационный текст (`info`) | без баллов |
| Слово из букв (`letters`), фраза из слов (`words`) | авто |
| Поиск в тексте (`find`) | авто: отметить нужные слова |
| Кейс (`case`) | вручную: эталон и критерии с баллами, проверяющий отмечает критерии |

Админ может «Попробовать» любой вопрос (предпросмотр с проверкой). Формат JSON для импорта описан в [docs/IMPORT_FORMAT.md](docs/IMPORT_FORMAT.md).

## Банк вопросов и переаттестация

- **«Управление → Банк вопросов»** — вопросы и кейсы вне экзаменов (`questions.exam_id = 0`). У каждого есть категория (ПК, УК, ТК, ВУ, СУ, ДУ, КПС, КоАП, «ФЗ …», «ФКЗ …»), вид (вопрос / кейс) и флаг активности.
  Вопросы можно добавлять, редактировать, проверять, импортировать и экспортировать JSON. Кнопка «Удалить ПРИМЕРЫ» удаляет заглушки `example-*`.
- **«Переаттестация»** (меню кандидата) — список включённых переаттестаций с отметкой «Показывать кандидатам». В каждой попытке вопросы выбираются случайно по квотам, без повторов; порядок вопросов и вариантов перемешивается.
- **«Управление → Переаттестация»** — админ создаёт, редактирует, включает/выключает и удаляет переаттестации (таблица `reattestations`):
  название, описание, блоки квот (категории банка через запятую, `ФЗ*` — префикс; число вопросов и кейсов; «предпочтительные типы, из них N» — сколько вопросов блока брать сначала из отмеченных типов), лимит времени, проходной %, пауза, лимит попыток,
  баллы за вопрос / за кейс (пусто — как в банке; критерии кейса пересчитываются пропорционально), «Показывать кандидатам», порядок в списке; пробная выборка по текущим значениям формы.
  Стандартные записи (миграции 0005–0006) редактируются как обычные:
  **полная**: ПК 5, УК 5, ВУ 10, СУ 3, КПС 3, ДУ 3, ФЗ/ФКЗ/КоАП 8, ТК 5. Это 42 вопроса без кейсов; бывшие слоты кейсов отданы под соответствие, порядок, число и несколько ответов. Проверяется автоматически.
  **упрощённая**: ВУ 9, СУ 2, ДУ 2, КПС 2. Это 15 вопросов, проверка автоматическая.
  **по кейсам**: ПК 1, УК 1, ВУ 2, СУ 1, КПС 1, ДУ 1, ФЗ/ФКЗ/КоАП 2, ТК 1. Это 10 кейсов; экзаменатор проверяет их по критериям.
  Попытка только из автотипов завершается сразу: итог виден после отправки, без статуса «на проверке».
  Удаление переаттестации, по которой есть попытки, — мягкое: попытки остаются в «Проверке» (вкладка с пометкой «удалена»). Попытки — в «Проверке» (фильтр «Переаттестация» и по каждой); в разборе — итог по блокам.

## Доступ к переаттестации (миграция 0012)

- Пользователь с ролью «Переаттестация» **не видит ни одной переаттестации**, пока администратор не выдаст доступ: «Админка → Переаттестация → 🔑 Доступ».
- Выдача: кому (конкретный пользователь с ролью или «все с ролью»), **до какого момента** (МСК; кнопки «до конца дня», +1 ч, +3 ч, +24 ч, бессрочно) и **сколько попыток** (пусто — без ограничения; у общей выдачи — на каждого). Отзыв — кнопкой «Отозвать». Всё пишется в журнал (`reatt.grant`, `reatt.revoke`).
- Проверяется на сервере (`reatt_access`): без действующей выдачи `/api/reatt` пуст, старт — 403; попытки считаются по выдаче (`attempts.meta.grant`). Начатую попытку можно завершить и после окончания срока. Администраторы видят и проходят всё без выдачи.
- Составы (0012): полная — 28 вопросов (ПК 4, УК 3, ВУ 6, СУ 2, КПС 2, ДУ 2, ФЗ/ФКЗ/КоАП 6, ТК 3), в первую очередь «один верный ответ», 60 мин; упрощённая — 12 (ВУ 6, СУ 2, ДУ 2, КПС 2), 30 мин; «кейсы» без изменений.
- Название портала — «ГУ ВП — портал», приветствие на странице входа убрано (пустое `welcome_text` не выводится).
- Лекции: шрифт Golos Text, 18 px, межстрочный 1.7, строка до 72 знаков, кнопки A−/A+ (запоминаются).

## Роли и разделы (миграция 0008)

Навигация — **шторка** (кнопка ☰ слева в шапке, на телефоне выезжает поверх страницы, закрывается ✕, Esc или тапом мимо). В шторке только те разделы, на которые у пользователя есть роль. Права проверяются **на сервере** (`caps()`/`requireCap()` в worker), скрытие в меню — только удобство.

Роли назначает администратор на странице пользователя («Админка» → «Пользователи и роли»); у одного человека их может быть несколько:

| Роль | Поле | Что открывает |
|---|---|---|
| ВП | `users.vp` | Учебный отдел (курсы, лекции, экзамены), Отчёты, Премирование, Система повышения (просмотр) |
| Переаттестация | `users.reatt` | Переаттестация |
| Руководство ГУ ВП | `users.leader` | «Руководство»: проверка и удаление отчётов, фонд, премии, бюджет, нарушения, состав |
| Проверяющий | `users.role = examiner` | Админка: проверка попыток, пользователи (просмотр) |
| Администратор | `users.role = admin` | Всё: содержимое сайта, роли, профили, курсы, База данных, Система повышения + все разделы выше |

Главные администраторы (`ADMIN_IDS`) имеют всё; таблицы выплат меняют только они. Без ролей пользователь видит только «Главную», «Базу данных» и свой профиль («Личные дела» — только старший состав). При миграции 0008 всем существующим пользователям выданы «ВП» и «Переаттестация», чтобы никто не потерял доступ; новые пользователи приходят без ролей.

Разделы:
- **Учебный отдел** (`#/study`, ВП) — курсы: карточки с прогрессом → курс = лекции по порядку (шаги) и экзамен в конце, он открывается после обязательных лекций курса. Курсы ведёт администратор («Админка» → «Курсы»: состав и порядок лекций, экзамен, видимость). При миграции каждый существующий экзамен стал курсом со своими лекциями.
- **Переаттестация** (`#/reatt`, роль «Переаттестация»).
- **Отчёты** (`#/reports`, ВП) — статус своего отчёта за неделю, комментарий и незасчитанные пункты, история; заполняется на сайте бланков.
- **Премирование** (`#/premiums`, ВП) — список премий недели для всех ВП: открывается **после срока (вс 19:00 МСК)**, только принятые отчёты, сданные в срок. Кто, звание, должность, план, оклад, действия, вычет, надбавки, благодарности и «За что» (пункты отчёта). Суммы (и своя итоговая сумма) показываются, когда руководство проверило **все** отчёты недели, сданные в срок. Наградная из бюджета ГУ ВП — отдельной колонкой и отдельным итогом.
- **Система повышения** (`#/promo`, ВП) — ступени, баллы, обязательные пункты; администратор меняет их (`#/promo?edit=1`). Изменения применяются и в «Рапорте на повышение» сайта бланков (`GET /api/promo-config`); без изменений действует `promo-rules.js`.
- **База данных** (`#/docs`, все) — статьи по разделам с поиском; добавляют и правят администраторы (простая разметка: `#`, `-`, `**`, ссылки).
- **Личные дела** (`#/people`, только старший состав) — досье сотрудников ГУ ВП. Подробно — раздел «Личные дела (миграция 0010)».
- **Руководство** (`#/lead`), **Админка** (`#/admin`), **Профиль** (`#/profile`: Имя Фамилия, звание, статик, должность — подставляются в отчёт и бланки; администратор может изменить их любому сотруднику, все изменения пишутся в журнал профиля).

## Личные дела (миграция 0010)

Досье сотрудника ГУ ВП (`dossier.js`, API `/api/people…`, таблицы `dossiers`, `dossier_events`).

- **Кто видит и ведёт дела — «старший состав» (`caps.ss`)**: роль «Руководство ГУ ВП», администраторы / главные администраторы и сотрудники с отметкой **«СС»** в «Отчёты и премии → Состав» (`users.senior`, ставит руководство). Отдельной роли не заводили. Все проверки — на сервере. Своё дело сотрудник СС не правит (кроме администраторов) — чтобы не снимать себе взыскания.
- **Дело** заводится только на сотрудника ГУ ВП (роль «ВП» или «в составе»): «Завести дело» в списке. При увольнении — **«В архив»** с причиной (дело остаётся, видно в фильтре «Архив», можно вернуть). Миграция 0010 завела дела на всех текущих пользователей с ролью «ВП» / в составе.
- **Ручные поля** (только СС): Имя Фамилия, статик, звание, должность (это поля профиля — правятся там же, с журналом), дата вступления в ГУ ВП, возраст (ИРЛ), часовой пояс, средний онлайн (ч/день и обычное время), Discord, личные ТС (модель + номер), служебные автомобили ВП (модель + номер + основной/доп.), оценка знания законодательства 1–5 + комментарий, характеристика / заметки (Markdown).
- **Ручная история** (только СС): взыскания (замечание, предупреждение, выговор, строгий выговор…; снимаются с основанием, можно вернуть), поощрения, повышения / понижения / переводы (звание и должность «с → на»; новое звание/должность сразу пишутся в профиль), заметки. Каждая запись — дата, кем выдано, причина/основание, ссылка на доказательство. Ошибочную запись можно удалить (мягко, остаётся в журнале).
- **Взыскания и нарушения по отчётам**: ручные взыскания показываются **рядом** с авто-нарушениями (в карточке, списке, «Руководство → Нарушения»), но в лестницу «1 — предупреждение, 2 — выговор, 3 — увольнение» за несданные отчёты не входят — это разные основания.
- **Автоматически**: еженедельные отчёты (неделя, дата отправки, в срок/поздно, уровень плана, баллы, премия — если неделя проверена, статус), авто-нарушения, попытки экзаменов и переаттестаций, «знание законодательства по тестам» (средний / лучший %), прогресс курсов и лекций, журнал изменений профиля и дела.
- **Хронология** всех событий + вкладки: Общее, Хронология, Транспорт, Отчёты, Взыскания и поощрения, Служба, Обучение, Журнал. Список — поиск, фильтры по должности, «есть активные взыскания», «Архив».
- **Кто видит**: раздел целиком (список, карточки, вкладки, хронология, журнал) — **только старший состав**; для него видны все поля. Всем остальным, включая самого сотрудника (своё дело он тоже не видит), все `/api/people…` отвечают 403, пункта в шторке и ссылок на дела нет. В журнал значения возраста, часового пояса, оценки и характеристики не пишутся — только факт изменения.

## Курсы, текстовые лекции, экзамены из банка, topic (миграция 0009)

- **Текстовая лекция** — лекция без видео, но с текстом (`lectures.body`, Markdown: `#`/`##` заголовки, списки, `**жирный**`, `*курсив*`, `>` цитаты, таблицы `|`, ссылки).
  Засчитывается по **времени чтения** (`duration_sec`, в админке — кнопка «По тексту (200 слов/мин)»): таймер идёт, только пока вкладка активна,
  сервер принимает прирост через тот же heartbeat, что у видео (не быстрее реального времени), поэтому «пролистать» лекцию нельзя.
- **Экзамен из банка** — `exams.bank_category` (категории через запятую, `*` — префикс) + `exams.bank_count`: каждая попытка берёт `bank_count` случайных вопросов банка, порядок случайный, варианты перемешиваются (если включено).
- **`questions.topic`** — группа вариантов одного вопроса. В одной попытке не бывает двух вопросов с одинаковым `topic`: это действует в экзаменах из банка, в переаттестациях (`sampleReatt`, в т. ч. между блоками) и в обычных экзаменах (из группы берётся один случайный вопрос). Пустой `topic` — без ограничений. Поле принимается импортом JSON (`topic`) и сохраняется при правке вопроса.

## Отчёты и премии (единая экосистема с сайтом отчётов)

Сайт бланков [vp-raport-offline](https://reflektpro.github.io/vp-raport-offline/) и этот учебный сайт работают вместе: шторка с разделами обоих сайтов, общий вход через Discord и общая сессия (оба сайта на `reflektpro.github.io`, токен под одним ключом `vpexam_token`). Имя, звание, статик и должность подставляются в бланки из профиля, а при отправке отчёта сервер берёт их из профиля, если он заполнен.

**Сотрудник:**
- На странице «Отчёт» сайта бланков нажимает **«Отправить отчёт»**. Если он ещё не вошёл, сначала входит через Discord.
- PDF и PNG по-прежнему выгружаются без входа.
- Отправляются: неделя (пн–вс), должность (одна из 7 из таблицы окладов), шапка и все пункты с количеством и ссылками.
- Повторная отправка за ту же неделю правит тот же отчёт. Прошлые версии хранятся в `report_history`.
- Опоздание определяется по первой отправке: срок — воскресенье 19:00 МСК. Отчёт после срока сохраняется, но премии нет.
- Сотрудник видит статус отчёта (отправлен / на проверке / принят / отклонён), комментарий руководства и незасчитанные пункты.

**«Руководство ГУ ВП»:**
- Роль назначает администратор: флажок на странице пользователя, поле `users.leader`.
- Главные администраторы и администраторы видят всё. Раздел `#/lead` («Руководство») включает:
  - **Неделя и премии.** Сводная таблица: должность, количество по каждому пункту (по группам), баллы, план (нет / минимальный / нормальный, чего не хватает), оклад, действия, вычет, база, доп., наградная, СС, наградная из бюджета, «Итого из фонда» и отдельно — «Наградная (бюджет ГУ ВП)»: она идёт из другого источника и в итог из фонда не входит (ни в строке, ни в общем итоге, ни в экспорте). Подсветка опоздавших и не сдавших. Также здесь фонд недели (8–20 млн), остаток, перенос остатка в бюджет и экспорт CSV/XLSX.
  - **Отчёт.** Каждый пункт можно принять, отклонить или принять частично (n из N), с комментарием. Должность можно исправить, отчёт целиком — принять или отклонить. Видна история правок. Пересчёт мгновенный.
    **«Удалить отчёт»** (с подтверждением и причиной) — для недостоверных отчётов: полная копия и история правок уходят в `reports_deleted`, действие — в журнал (`report.delete`), премии и фонд недели пересчитываются сразу. Неделя у сотрудника становится «без отчёта» (нарушение, если не снять); он может сдать заново (после срока — уже с опозданием). Если остаток фонда уже был перенесён в бюджет, таблица предупредит, что его надо перенести заново.
  - **Нарушения.** Недели без отчёта в срок с начала учёта сотрудника: 1 — предупреждение, 2 — выговор, 3 — увольнение. Нарушение можно снять. В Discord ничего не отправляется.
  - **Бюджет ГУ ВП.** Взносы СС (минимум 150 000 в неделю; кто не внёс — отмечается), остатки фонда, поступления, снятия (с примечанием), наградные из бюджета. Удаление мягкое, всё пишется в журнал аудита.
  - **Состав.** Кто в составе (обязан сдавать отчёт), кто СС, должность для тех, кто без отчёта, с какой недели вести учёт.
  - **Таблицы выплат.** Оклады (Т0), выплата за действие (Т1–Т2) по каждому пункту отчёта, строки плана и какие пункты в них засчитываются, правила и лимиты. Менять может только главный администратор; кнопка «Вернуть значения приказа» сбрасывает изменения.

**Расчёт** (`computePremiums` в `worker/worker.js`; тесты в `tests/prem-unit.js`):
1. Отчёт без минимального плана: нулевой оклад + выплаты за действия − 50%. Минимальный план: минимальный оклад + действия − 20%. Нормальный план: средний оклад + действия полностью.
2. База (оклад + действия) не больше максимальной выплаты должности. База выплачивается всегда, даже если фонда не хватает.
3. Дальше по очереди, пока хватает фонда: дополнительная премия (превышение над максимумом, не больше 400 000; при нехватке делится пропорционально) → наградная из фонда (100 000–700 000, вписывает руководство) → премия СС (до 500 000, только СС). Надбавки, на которые не хватает, урезаются.
4. Лимит 2 000 000 на человека: оклад + премия + доп. + наградная. Премия СС и наградная из бюджета ГУ ВП в лимит не входят.
5. Благодарность от руководства: 50 баллов = 1 благодарность = 2 500 ₽ (как выплата за действие). На форме можно ввести баллы, количество посчитается само.
6. Строки плана по умолчанию:
   - «Мероприятия внутри ВС РФ» = МП + тренировка + профилактическое (ГМП не входит);
   - «Реанимации» = ПМП;
   - «Действия ГУ ВП» = все пункты «Работы ГУ ВП» + проц. действия + тренировки.

   Один пункт может засчитываться в несколько строк.

## Как наполнить сайт (через «Админку»)

1. **Видео.** Поддерживаются:
   - **YouTube (рекомендуется).** Загрузите ролик на YouTube с доступом **«По ссылке» (Unlisted)** — в поиске его не будет, но плеер на сайте работает.
     Подходят ссылки `youtube.com/watch?v=…`, `youtu.be/…`, `/shorts/…`, `/embed/…` (сохраняются в едином виде).
     В YouTube Studio должно быть включено «Разрешить встраивание», иначе плеер покажет ошибку 101/150.
     Длительность определяется автоматически (YouTube IFrame API, `getDuration()`).
     Плеер YouTube встраивается без своих кнопок (`controls=0`, `disablekb=1`), поверх лежит прозрачный «щит», управление — только нашими кнопками;
     позиция опрашивается 4 раза в секунду, попытка уйти вперёд дальше просмотренного откатывается, скорость сбрасывается на 1×.
   - **Прямая ссылка на файл** `.mp4` (H.264/AAC) или `.webm` на любом хостинге (сервер должен поддерживать Range-запросы),
     либо файл в папке `videos/` этого репозитория (до ~90 МБ) — ссылка `videos/lecture1.mp4`. Длительность читается из метаданных файла.
   - **Не подходят** (сайт откажет с объяснением): Google Диск (не отдаёт видео встроенному плееру), Discord CDN (ссылки истекают через сутки),
     VK/Rutube/Twitch/Яндекс.Диск.
   R2 на аккаунте Cloudflare сейчас не включён, поэтому загрузки видео через сайт нет (см. «Ограничения»).
2. **Лекции:** «Лекции» → «Добавить лекцию»: название, описание, ссылка (длительность подставится сама; можно ввести вручную — секунды, `мм:сс` или `чч:мм:сс`), «Обязательная», «Опубликована».
   Внизу формы — блок **«Статус»**: «Сохранить черновик» (кандидаты не видят) или «Опубликовать». В списке лекций/экзаменов есть быстрые кнопки «Опубликовать» / «Снять с публикации».
   Черновик сохраняется даже без видео и длительности. Для публикации нужны ссылка и длительность > 0; ошибки сервера показываются прямо под формой.
   Порядок — стрелками ↑↓. Лекции открываются строго по порядку (выключается в «Настройках»).
3. **Экзамен:** «Экзамены» → «Создать экзамен» → «Сохранить черновик» → добавить вопросы (для вариантов — отметить правильные; для текстовых — эталон для проверяющего) → «Опубликовать» (без вопросов опубликовать нельзя).
4. **Проверка:** «Проверка» → попытка → баллы за текстовые ответы (можно переопределить и автобаллы) → решение «По баллам» / «Сдан» / «Не сдан» + комментарий.
5. **Кандидаты:** поиск, прогресс по лекциям, сброс прогресса (одной лекции или всех), удаление попыток, роль, блокировка.
6. **Настройки:** название сайта, приветствие, последовательное открытие лекций. **Журнал** — все действия админов.

## Ограничения

- Защита от перемотки не абсолютна: пользователь с навыками может слать heartbeat скриптом, но не быстрее реального времени —
  то есть «пропустить» лекцию можно, лишь потратив то же время (видео при этом может не смотреть). Смотреть, слушает ли человек, сервер не может.
- Для YouTube защита слабее, чем для файла: продвинутый пользователь может открыть ролик напрямую на YouTube и посмотреть его там, но лекция засчитывается только по heartbeat нашего плеера (в реальном времени). Сам ролик «По ссылке» доступен любому, у кого есть ссылка.
- Прямая ссылка на видео доступна вошедшему кандидату (её можно скачать). Для закрытой раздачи нужен R2 (включить в Cloudflare Dashboard)
  с выдачей видео через Worker — заготовки нет, можно добавить позже.
- Если кандидат пересматривает уже засчитанную лекцию, прогресс не сбрасывается.
- Лимиты запросов реализованы через D1 (не через Cloudflare Rate Limiting) — для небольшой фракции этого достаточно.
- Файлы и голосовые ответы хранятся в D1 (base64, до 1 МБ на файл), потому что R2 не включён. Для больших файлов кандидат может дать ссылку.
- «Последовательное исключение» оценивается по итоговому оставшемуся варианту. Пошаговой проверки на сервере нет.
- Кейс по умолчанию весит `max_score` (обычно 10), а обычный вопрос — 1 балл. Вес меняется полем «Баллы» у вопроса.
- В кейсах по уставам, где критерий нельзя разбить на пункты, есть два уровня: «Полный ответ» (10) и «Частично» (5). Отмечать нужно один из них, баллы ограничены максимумом.
