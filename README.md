# ГУ ВП — Учебный центр (лекции и экзамены)

Отдельный сайт для кандидатов в ГУ ВП (RMRP, «Патрики»): вход через Discord → просмотр лекций без перемотки → экзамен → проверка экзаменатором.
Не связан с сайтом рапортов (vp-raport / curly-disk-ebd7) — свой Worker, своя база, своё Discord-приложение (или общее, см. ниже).

| Что | Где |
|---|---|
| Сайт (GitHub Pages) | https://reflektpro.github.io/vp-exam/ |
| API (Cloudflare Worker) | https://vp-exam-api.reflektpro8.workers.dev |
| База (Cloudflare D1) | `vp-exam-db`, id `ce68b5b2-5aa7-4b69-9f7a-edb1b1744cb9` |
| Discord Redirect URI | `https://vp-exam-api.reflektpro8.workers.dev/auth/callback` |
| Главные администраторы | Discord ID `417660389723996170`, `711459160268734505` (переменная `ADMIN_IDS`) |

## Как включить вход через Discord (обязательно, сейчас вход выключен)

Пока не заданы ключи, API отвечает «OAuth не настроен», а кнопка входа на сайте неактивна.

1. Откройте https://discord.com/developers/applications.
   - **Вариант А (рекомендуется):** «New Application» → назовите, например, «ГУ ВП Учебный центр».
   - **Вариант Б:** взять существующее приложение сайта рапортов. Тогда нужен его *текущий* Client Secret.
     ⚠️ Не нажимайте «Reset Secret» в существующем приложении — иначе сломается вход на сайте рапортов.
2. В приложении: **OAuth2 → Redirects → Add Redirect** и вставьте ровно:
   `https://vp-exam-api.reflektpro8.workers.dev/auth/callback` → **Save Changes**.
3. Там же скопируйте **Client ID** и **Client Secret** (для нового приложения — «Reset Secret», чтобы показать его).
4. Cloudflare Dashboard → **Workers & Pages → vp-exam-api → Settings → Variables and Secrets → Add**:
   - `DISCORD_CLIENT_ID` — тип **Secret** (можно Text, но Secret сохраняется при повторных деплоях через API);
   - `DISCORD_CLIENT_SECRET` — тип **Secret**.
   → **Deploy**. Или из консоли: `npx wrangler secret put DISCORD_CLIENT_ID` и `npx wrangler secret put DISCORD_CLIENT_SECRET` в папке `worker/`.
5. Проверка: https://vp-exam-api.reflektpro8.workers.dev/health должно показать `"oauth_configured":true`, а на сайте кнопка «Войти через Discord» станет активной.

Запрашиваемый scope — только `identify` (ID, ник, аватар).

## Архитектура

```
GitHub Pages (статический HTML/JS/CSS, без сборки)        Cloudflare Worker vp-exam-api            D1 vp-exam-db
index.html, app.js, player.js, admin.js, style.css  ──►  worker/worker.js (один ES-модуль)  ──►  users, sessions, lectures,
config.js (адрес API)        Authorization: Bearer        CORS только https://reflektpro.github.io     lecture_progress, exams, questions,
                                                                                                    attempts, answers, settings, audit_log
```

**Вход:** сайт → `GET /auth/login?return=<url сайта>` → Discord → `GET /auth/callback` (worker меняет code на токен Discord, читает `/users/@me`,
создаёт/обновляет пользователя, выдаёт одноразовый `login_code` на 2 минуты) → редирект на сайт `?login_code=…` → сайт делает
`POST /auth/exchange` и получает сессионный токен (хранится в `localStorage`, в базе — только SHA-256 хеш; срок 7 дней).
Cookie не используются (разные домены github.io / workers.dev), поэтому CSRF неактуален. `state` OAuth хранится в D1 (10 минут).

**Роли:** `candidate` (по умолчанию), `examiner` (проверка попыток, просмотр кандидатов), `admin` (всё).
ID из `ADMIN_IDS` всегда `admin` и не могут быть понижены/заблокированы через сайт. Назначать/снимать админов может только главный админ;
обычный админ может назначать проверяющих. Права проверяются на сервере в каждом запросе `/api/admin/*`.

**Защита от перемотки лекций:**
- Клиент: свой плеер без полосы перемотки (пуск/пауза, «назад 10 с», громкость, полный экран; скорость зафиксирована 1×),
  попытка перемотать вперёд дальше уже просмотренного откатывается, назад — можно. Продолжение с последней позиции.
  Видео ставится на паузу при скрытии вкладки (`PAUSE_ON_HIDDEN` в `config.js`).
- Сервер: плеер шлёт heartbeat каждые 10 с и при play/pause/ended. Прирост позиции принимается, только если он
  ≤ `реальное время с прошлого heartbeat × 1.1 + 2 с` и ≤ 40 с за раз. Иначе — отказ и откат (счётчик отказов виден админу).
  Лекция засчитана, когда `max_pos ≥ длительность − 3 с` **и** засчитанное время просмотра ≥ 95 % длительности.
- Длительность задаёт админ (кнопка «Определить по видео» читает её из файла). Если длительность указана больше реальной, лекцию нельзя будет досмотреть — проверяйте.

**Экзамен:** 20 типов вопросов (см. «Типы вопросов» ниже). Параметры: лимит времени, лимит попыток,
пауза между попытками, проходной %, перемешивание вопросов/вариантов, **«Обязательные лекции»**, публикация.

**Обязательные лекции экзамена** (блок в форме экзамена):
- «Все опубликованные лекции» — по умолчанию и для всех старых экзаменов: нужны все опубликованные лекции с отметкой «Обязательная» (как раньше, включая будущие).
- Галочки у отдельных лекций — экзамен откроется после просмотра только выбранных. Черновики и удалённые лекции не учитываются; в списке экзаменов про них показывается предупреждение.
- Ничего не отмечено и «все» выключено — экзамен открыт сразу, без лекций.
- Проверка выполняется на сервере при открытии карточки, старте и отправке попытки. Кандидат видит на карточке экзамена, какие лекции просмотрены и что «Осталось посмотреть» (со ссылками).
- Настройка «Открывать лекции строго по порядку» влияет только на очерёдность просмотра лекций, а не на допуск к экзаменам. Если нужная экзамену лекция стоит третьей, кандидату всё равно придётся посмотреть первые две, чтобы её открыть (на карточке такие лекции отмечены 🔒).
Правильные ответы и эталоны никогда не отправляются кандидату. Варианты проверяются автоматически (multi — только точное совпадение),
текстовые идут на ручную проверку. Таймер проверяется на сервере: после дедлайна (+30 с запаса) попытка завершается автоматически
с сохранёнными ответами (ответы автосохраняются каждые 15 с). Пока попытка на проверке или экзамен сдан — новая попытка не начинается.
Кандидат видит итог (СДАН / НЕ СДАН / НА ПРОВЕРКЕ), процент и комментарий проверяющего, но не разбор по вопросам.

## Типы вопросов

Все типы работают и в экзаменах, и в переаттестации. Проверка выполняется на сервере, правильные ответы клиенту не отправляются. Для каждой попытки сохраняется своё перемешивание и свои параметры.

| Тип | Проверка |
|---|---|
| Одиночный / множественный выбор (`single`/`multi`) | авто (multi — точное совпадение или частичный балл, если включён `partial`) |
| Ввод числа (`number`) | авто, допуск ±tolerance, единица, принимается десятичная запятая |
| Ввод текста (`text`) | авто, список допустимых ответов; регистр, ё/е и крайняя пунктуация не важны |
| Параметризованная задача (`param`) | авто: переменные `{A}` берутся случайно из диапазонов, ответ считается по формуле |
| Свободная форма (`long`) | вручную, проверяющий видит эталон |
| Последовательность (`order`) | авто; перетаскивание или стрелки ↑↓ (удобно на телефоне) |
| Соответствия (`match`) | авто, можно добавить лишние варианты |
| Пропуски — ввод / из списка (`blanks_input`/`blanks_select`) | авто, разметка `[[ответ|синоним]]` / `[[неверно|*верно]]` |
| Интерактивный диктант (`dictation`) | авто, выбор буквы или слова прямо в тексте |
| Последовательное исключение (`eliminate`) | авто: кандидат вычёркивает варианты, пока не останется один |
| Слайдер (`slider`) | авто, допуск ±tolerance |
| Загрузка файла (`file`) | вручную. Файл хранится в D1 (base64, ≤ 1 МБ), можно дать ссылку |
| Голосовой ответ (`voice`) | вручную. Запись в браузере (MediaRecorder) или загрузка аудиофайла, ≤ 1 МБ |
| Информационный текст (`info`) | без баллов |
| Слово из букв (`letters`), фраза из слов (`words`) | авто |
| Поиск в тексте (`find`) | авто: отметить нужные слова |
| Кейс (`case`) | вручную: эталон и критерии с баллами, проверяющий отмечает критерии |

Админ может «Попробовать» любой вопрос (предпросмотр с проверкой). Формат JSON для импорта описан в [docs/IMPORT_FORMAT.md](docs/IMPORT_FORMAT.md).

## Банк вопросов и переаттестация

- **«Управление → Банк вопросов»** — вопросы и кейсы вне экзаменов (`questions.exam_id = 0`). У каждого есть категория (ПК, УК, ТК, ВУ, СУ, ДУ, КПС, КоАП, «ФЗ …», «ФКЗ …»), вид (вопрос / кейс) и флаг активности.
  Вопросы можно добавлять, редактировать, проверять, импортировать и экспортировать JSON. Кнопка «Удалить ПРИМЕРЫ» удаляет заглушки `example-*`.
- **«Переаттестация»** (меню кандидата) — список включённых переаттестаций с отметкой «Показывать кандидатам». В каждой попытке вопросы выбираются случайно по квотам, без повторов; порядок вопросов и вариантов перемешивается.
- **«Управление → Переаттестация»** — админ создаёт, редактирует, включает/выключает и удаляет переаттестации (таблица `reattestations`):
  название, описание, блоки квот (категории банка через запятую, `ФЗ*` — префикс; число вопросов и кейсов), лимит времени, проходной %, пауза, лимит попыток,
  баллы за вопрос / за кейс (пусто — как в банке; критерии кейса пересчитываются пропорционально), «Показывать кандидатам», порядок в списке; пробная выборка по текущим значениям формы.
  Стандартные записи из миграции 0005: **полная** (ПК 4+1, УК 4+1, ВУ 8+2, СУ 2+1, КПС 2+1, ДУ 2+1, ФЗ/ФКЗ/КоАП 6+2, ТК 4+1) и **упрощённая** (ВУ 9, СУ 2, ДУ 2, КПС 2 + 3 кейса по уставам) — редактируются как обычные.
  Удаление переаттестации, по которой есть попытки, — мягкое: попытки остаются в «Проверке» (вкладка с пометкой «удалена»). Попытки — в «Проверке» (фильтр «Переаттестация» и по каждой); в разборе — итог по блокам.

## Как наполнить сайт (через «Управление»)

1. **Видео.** Поддерживаются:
   - **YouTube (рекомендуется).** Загрузите ролик на YouTube с доступом **«По ссылке» (Unlisted)** — в поиске его не будет, но плеер на сайте работает.
     Подходят ссылки `youtube.com/watch?v=…`, `youtu.be/…`, `/shorts/…`, `/embed/…` (сохраняются в едином виде).
     В YouTube Studio должно быть включено «Разрешить встраивание», иначе плеер покажет ошибку 101/150.
     Длительность определяется автоматически (YouTube IFrame API, `getDuration()`).
     Плеер YouTube встраивается без своих кнопок (`controls=0`, `disablekb=1`), поверх лежит прозрачный «щит», управление — только нашими кнопками;
     позиция опрашивается 4 раза в секунду, попытка уйти вперёд дальше просмотренного откатывается, скорость сбрасывается на 1×.
   - **Прямая ссылка на файл** `.mp4` (H.264/AAC) или `.webm` на любом хостинге (сервер должен поддерживать Range-запросы),
     либо файл в папке `videos/` этого репозитория (до ~90 МБ) — ссылка `videos/lecture1.mp4`. Длительность читается из метаданных файла.
   - **Не подходят** (сайт откажет с объяснением): Google Диск (не отдаёт видео встроенному плееру), Discord CDN (ссылки истекают через сутки),
     VK/Rutube/Twitch/Яндекс.Диск.
   R2 на аккаунте Cloudflare сейчас не включён, поэтому загрузки видео через сайт нет (см. «Ограничения»).
2. **Лекции:** «Лекции» → «Добавить лекцию»: название, описание, ссылка (длительность подставится сама; можно ввести вручную — секунды, `мм:сс` или `чч:мм:сс`), «Обязательная», «Опубликована».
   Внизу формы — блок **«Статус»**: «Сохранить черновик» (кандидаты не видят) или «Опубликовать». В списке лекций/экзаменов есть быстрые кнопки «Опубликовать» / «Снять с публикации».
   Черновик сохраняется даже без видео и длительности. Для публикации нужны ссылка и длительность > 0; ошибки сервера показываются прямо под формой.
   Порядок — стрелками ↑↓. Лекции открываются строго по порядку (выключается в «Настройках»).
3. **Экзамен:** «Экзамены» → «Создать экзамен» → «Сохранить черновик» → добавить вопросы (для вариантов — отметить правильные; для текстовых — эталон для проверяющего) → «Опубликовать» (без вопросов опубликовать нельзя).
4. **Проверка:** «Проверка» → попытка → баллы за текстовые ответы (можно переопределить и автобаллы) → решение «По баллам» / «Сдан» / «Не сдан» + комментарий.
5. **Кандидаты:** поиск, прогресс по лекциям, сброс прогресса (одной лекции или всех), удаление попыток, роль, блокировка.
6. **Настройки:** название сайта, приветствие, последовательное открытие лекций. **Журнал** — все действия админов.

## Деплой и миграции

- Схема: `worker/migrations/0001_init.sql` (идемпотентна, `CREATE TABLE IF NOT EXISTS`). Новые изменения схемы — новыми файлами `0002_…sql`.
  `0002_exam_lectures.sql` — столбец `exams.lecture_mode` (по умолчанию `'all'`) и таблица `exam_lectures(exam_id, lecture_id)`; применяется один раз (содержит `ALTER TABLE … ADD COLUMN`).
  `0003_question_types_reatt.sql` — новые столбцы `questions` (data, category, kind, easy, active, ext_id, created_at, updated_at), `attempts` (reatt, meta) и таблица `uploads`; применяется один раз.
  `0005_reattestations.sql` — таблица `reattestations` с записями `full`/`simple`; `questions.easy` обнулён и не используется.
  `0004_seed_examples.sql` — заглушки «ПРИМЕР» в банке (идемпотентно; генерируется `node tools/gen-seed.js`).
  Применить: `cd worker && npx wrangler d1 migrations apply vp-exam-db --remote` (или выполнить SQL в консоли D1).
- Worker: `cd worker && npx wrangler deploy` (конфиг `worker/wrangler.toml`). Секреты при деплое сохраняются.
- Сайт: push в `main` → GitHub Pages публикует из корня. Адрес API — в `config.js`.
  После коммита изменений выполните `sh tools/bump-version.sh && git commit -am "версия"` — это проставит `?v=<sha>` в ссылки на JS/CSS и `version.json`;
  открытые вкладки сами предложат «Обновить», когда выйдет новая версия (GitHub Pages кэширует index.html до 10 минут).

## Ограничения

- Защита от перемотки не абсолютна: пользователь с навыками может слать heartbeat скриптом, но не быстрее реального времени —
  то есть «пропустить» лекцию можно, лишь потратив то же время (видео при этом может не смотреть). Смотреть, слушает ли человек, сервер не может.
- Для YouTube защита слабее, чем для файла: продвинутый пользователь может открыть ролик напрямую на YouTube и посмотреть его там, но лекция засчитывается только по heartbeat нашего плеера (в реальном времени). Сам ролик «По ссылке» доступен любому, у кого есть ссылка.
- Прямая ссылка на видео доступна вошедшему кандидату (её можно скачать). Для закрытой раздачи нужен R2 (включить в Cloudflare Dashboard)
  с выдачей видео через Worker — заготовки нет, можно добавить позже.
- Если кандидат пересматривает уже засчитанную лекцию, прогресс не сбрасывается.
- Лимиты запросов реализованы через D1 (не через Cloudflare Rate Limiting) — для небольшой фракции этого достаточно.
- Файлы и голосовые ответы хранятся в D1 (base64, до 1 МБ на файл), потому что R2 не включён. Для больших файлов кандидат может дать ссылку.
- «Последовательное исключение» оценивается по итоговому оставшемуся варианту. Пошаговой проверки на сервере нет.
- Кейс по умолчанию весит `max_score` (обычно 10), а обычный вопрос — 1 балл. Вес меняется полем «Баллы» у вопроса.
- В кейсах по уставам, где критерий нельзя разбить на пункты, есть два уровня: «Полный ответ» (10) и «Частично» (5). Отмечать нужно один из них, баллы ограничены максимумом.
